# Phase 1: Coverage gate - Plan 4: Fake servers that bind without a name lookup

## Goal

The existing suite runs unattended on a macOS runner, and the fork-owned modules meet the accepted 85% lines and branches floor. This gap plan closes the last part of UAT item 4, cluster (a). On run 42341370023 at 75b8a6c, 14 launcher and quit tests failed (`14 failed, 578 passed, 11 skipped`) because their fake server "didn't start", and every log was empty. The owner diagnosed the cause from instrumented run 42346423614. The plan records that cause, fixes every server in `tests/` that binds the same way, proves the fix on Slate without relying on Slate's fast resolver, and ends with a pushed `personal` commit whose `tests` job passes.

## Must be true when done

- UAT item 4's `cause:` names the diagnosed cause and its evidence (run 42346423614). It no longer reads "root causes unverified".
- No HTTP server in `tests/` calls `socket.getfqdn` when it binds. That covers the child-process fake servers behind all 14 cluster (a) tests and the in-process test servers. A local run with `socket.getfqdn` made to raise shows each one still starting.
- A fake server started on a port that is already taken still dies at bind, so the "never attaches to another Void" tests prove what they proved before.
- Locally on Slate, the two accepted commands from `.github/cadence/coverage-policy.json` exit 0 and print 14 `meets 85` lines for the 7 `include` files, and `planning.mjs test-policy check --root .` prints `"gate_found":true`.
- On a pushed `personal` commit, the `tests` job passes with its `Per-module floor` step run. Its `coverage.json` artifact gives 14 `meets 85` lines, and its `-rs` summary shows only `slow tier: set VOID_SCENES=1` skips (AC3, AC5, ci: tests).

## Context

- Binding: D-02 (both accepted commands verbatim, as separate steps, with no `continue-on-error`), D-07 (no speech model fetched) and D-08 (85/85 on all 7 modules, floor never lowered). The workflow, the coverage policy, its thresholds and its commands are not touched.
- Cause, from the owner's diagnosis of run 42346423614 on the debug branch `ci-debug/fake-servers` (e667dad). On macos-15, `http.server.HTTPServer.server_bind` runs `socketserver.TCPServer.server_bind` and then `socket.getfqdn(host)` on `"127.0.0.1"`. That call blocks for about 35 s in `mdns_hostbyaddr`, longer than every start wait: 5 s in `Launchers.foreign_server`, 8 s in `test_quit.py`'s `wait_for`, and 6 s in the launchers' own `seq 60` loops. The fake server is still in its bind when the wait gives up, before it has written anything, so its log is empty. `ThreadingHTTPServer` inherits that bind.
- The debug branch is evidence only. Nothing from it is merged, cherry-picked or copied (not `tests/debug/`, not `ci-debug.yml`, not its `diagnose` calls). This plan works on `personal`.
- Out of scope: `app/`. `app/server.py`'s `main` binds `ThreadingHTTPServer(("127.0.0.1", ...))` the same way. It is reported (Notes), not fixed, as Plan 3 did with app causes. No test in this plan runs it.

### Task 2: Bind the child-process fake servers without a name lookup

- **Files:** tests/loopback_http.py (new), tests/test_launchers.py (`FAKE_SERVER`), tests/test_quit.py (`FAKE_SERVER`)
- **Action:** Create `tests/loopback_http.py`. It holds the one copy of a bind that does what `HTTPServer.server_bind` does except the lookup. It calls `socketserver.TCPServer.server_bind` and then sets `server_name` and `server_port` from `server_address` itself; `server_name` is the bound host. Make it usable by both a threaded and a plain server, because Task 3's sites use both kinds. It inherits everything else from `http.server`, including `allow_reuse_address`, so a port another process is listening on still fails at bind. The module is stdlib-only, self-contained and has no side effects at import, so its text is valid as the head of a script. The bind lives once, here, and not in each file. Why: the same four lines would otherwise be copied into five sites in four files. The duplicated `Logs` helper already shows how such copies spread (phases/1/SUMMARY.md, phase 1, open items), and one module gives Task 2 and Task 3 a single thing to prove. Both `FAKE_SERVER` strings get the bind from this module's text, read from its path when the test module loads and placed ahead of the fake's own body. They do not import it at run time, because the real launchers run the fake as a lone `server.py` from the bundle's `Resources/app`, or from `data/void/app`, with `PATH=/usr/bin:/bin` and no path back to `tests/`. The fake stays as self-contained as the `app/server.py` it stands in for. Each fake's server is built through that bind, and nothing else in either fake changes: `signal.alarm`, runtime.json, the pid files, the `sleep 40` child, the handlers, and the `(port taken → dies here, like the real one)` behaviour. This one change covers every start of the 14 tests. `Launchers.foreign_server`, `Base.foreign_server` and `WindowKeepsTheRecord.start` run the string directly. `check_own_server`, `LauncherQuit` and `test_the_windows_restart_is_what_gets_recorded` run it through `packaging/macos/launcher`, `bin/void` and `window_win.VoidWindow._start_server`. Change no wait, timeout, env or assertion, and add no skip. The waits were never the cause.
- **Verify:** `UV_PYTHON=3.12 uvx --with-requirements tests/requirements.txt pytest tests/test_launchers.py tests/test_quit.py` passes with 18 tests, the same count as before. The `check_never_attaches` pair passing is the proof that a taken port still kills the fake at bind. Falsifiable check, independent of Slate's resolver: a scratch script in the session scratchpad, not committed. For each file's `FAKE_SERVER`, it writes the string to a temp `app/server.py` and starts it with `sys.executable` under a `-c` wrapper. The wrapper replaces `socket.getfqdn` with a function that raises, then runs the file as `__main__`, with the env `env()` builds (`HOME`, `XDG_DATA_HOME`, `PATH=/usr/bin:/bin`, `FAKE_PORT`). The script then waits 5 s for the file that file's tests wait on (`runtime.json` for test_launchers, `child.pid` for test_quit). Run against the strings at HEAD (`git show HEAD:<file>`), both fakes exit with the raised error in their output. Run against the changed tree, both start. The script records every PID it starts, the quit fake's `sleep 40` child included, kills them by PID and confirms with `ps -p` that none is left. The report quotes both runs' decisive lines. Testing scope: the 14 existing tests are the regression check on the runner, and the scratch run is the local proof. No permanent test is added, because a fake that brings the lookup back fails those 14 tests on the runner.

- Same-cause sweep: `grep` across `tests/`, `app/`, `bin/` and `packaging/` for `HTTPServer`, `TCPServer`, `socketserver` and `getfqdn` finds these sites. Two are the child-process fakes, `tests/test_launchers.py` `FAKE_SERVER` and `tests/test_quit.py` `FAKE_SERVER` (Task 2). Three are in-process: `tests/test_launchers.py` `WindowsLauncherUp.setUp`, `tests/test_wake_loop.py` `setUp` and `tests/test_agents.py` `ApproveHook` (Task 3). One is in `app/server.py` `main`, `ThreadingHTTPServer(("127.0.0.1", int(CFG["port"])), Handler)`. It has the same bind, so on a Mac where a reverse lookup of 127.0.0.1 is slow, the real server would write its runtime.json late by that lookup, past the launchers' 6 s wait. That is reported for the owner, not fixed here, because `app/` is outside this phase's lease.

# Phase 2: Branch split - Plan 1: Classification and the owner's rulings

## Goal

Every commit on `personal` that `macos` lacks is sorted into a fix bound for `macos` or personal-only work (visual, feature, dev tooling), each borderline call is ruled on by the owner, and a trial build proves the ruled fix set cherry-picks onto `macos`, passes the suite and merges back into `personal` cleanly before Plan 2 builds it for real.

## Must be true when done

- `.planning/phases/2/CLASSIFICATION.md` lists each SHA in `macos..<snapshot>` exactly once, with a class of `fix`, `visual`, `feature`, `dev tooling` or `merge`, and names the snapshot it covers
- The file names every path-split commit in its Path-split section and every line-split commit in its Line-split section, each with what it carries onto the fix branch and what it leaves behind
- A trial build of the fix set on `c895ced`, its suite and coverage run, and its trial merge back into `personal` are recorded in the file, each conflict or failure with the commit that causes it
- The Borderline section carries every call for the owner's ruling, and each row carries the owner's ruling
- The ruled set has a clean trial (no cherry-pick conflict or empty pick under the Trial section's Row construction, suite and per-module gate green, and a merge-back made by the Trial section's Merge-back prep on the scratch worktree, R and H first, with no conflict and no changed file, and after the revert of H no file changed from R), and no trial worktree or trial branch is left behind

## Context

- Locked: D-01 (hearing stack is fix-bound), D-02 (Phase 1 CI and tests ride the fix branch; `.planning/` stays), D-05 (every commit once; each merge its own row), D-06 (visual and feature stay; borderline listed), D-08 (cherry-pick in original order; `c378787` path-split; never cut from `personal` and reverted), D-10 (no other branch touched).
- The population is now 156 (137 non-merge, 18 merges, plus `a448780`, a `.planning/`-only commit made after CONTEXT counted 155). The orchestrator keeps committing `.planning/` files to `personal` during the phase, so the file pins a snapshot SHA and covers `macos..<snapshot>`.
- Personal-only paths: `CLAUDE.md`, `.claude/`, `queues/`, `docs/superpowers/`, `docs/design/`, `.planning/` (SPLIT-02 plus D-02).
- Out: pushing anything, `git fetch` or any remote touch; `stream/*`, `ci-debug/fake-servers` and agent worktree branches; the `tests` job and `.github/cadence/coverage-policy.json`.

### Task 2: Name the path-split commits

Construction for a path-split commit is `git cherry-pick -n <sha>`, then the personal-only paths are put back to the pre-pick state (restored from `HEAD` where they exist there, removed from the index and tree where the commit created them), then `git commit -C <sha>` keeps the original author and message. Never resolve a conflict by hand, and never edit a file to make a pick apply: CONTEXT's flagged assumption rules this out. When a pick conflicts, find the excluded commit that caused it. ## Notes

- AC1 is checked against `macos..<snapshot>`, not live `macos..personal`. The orchestrator's `.planning/` commits keep landing on `personal` during the phase, and a commit that updates the file can never list itself. Every commit after the snapshot touches only `.planning/` (dev tooling), and Plan 2 checks this before it builds.
- AC3 is checked by the Presence test (author, author date and subject), not by `git cherry` `-`, per `docs/superpowers/specs/branch-split-construction-design.md`. Path-split rows are listed only in the classification's Path-split section, and line-split rows only in its Line-split section.
- The trial, not a guess, decides the dependency calls. A fix that cherry-picks only on top of excluded work goes to the owner as a borderline row, never through a hand-resolved conflict (CONTEXT, flagged assumptions).
- The trial branch writes `app/`, `tests/` and `.github/` paths on a throwaway branch that Task 8 deletes. Those writes never reach a branch that persists, so this plan's lease is the classification file alone.
- Recalled: D-02 and D-04 (`phases/2/CONTEXT.md`, phase 2). The `tests` job is triggered on pushes to `macos` and `personal` with no `paths:` filter (`phases/1/UAT.md`, phase 1), so nothing here runs CI, because nothing is pushed.
